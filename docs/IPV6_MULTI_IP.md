## 1. 为什么这条路走得通

- **opencode zen 支持 IPv6**：本工具默认规则让 `opencode.ai` 及子域名强制走 IPv6。
- **国内运营商 IPv6 前缀**：移动/电信/联通的住宅宽带，光猫（光猫→路由）通常直接拿到 **/60**（部分 /56）前缀，即 16（或 256）个 /64 子网，每个子网地址近乎无限。
- **结论**：你本来就拥有海量公网 IPv6，只是默认只用了其中一个。本工具的作用就是把来源地址"换着用"，对服务端而言呈现为不同的源地址。

## 2. 核心认知（先看这个，避免走弯路）

**内核不会"随机"选源地址。** Linux/Windows 的源地址选择（RFC 6724）是确定性的：优先同前缀、优先级标签、隐私地址等。即使网卡上配了几千个地址，什么都不做的话，出站连接也只会固定用"首选"的那一个。

> 想通过本工具实现随机出口，必须有一个显式干预点。只有三种：SNAT 地址池 / 应用层绑定 / 路由策略。

## 3. 前提：先确认你的前缀情况

在光猫/路由器上找 IPv6 设置（WAN 侧），判断：

| 情况 | 说明 | 可行性 |
|---|---|---|
| `/60` 或 `/56`（PD 前缀委派） | 光猫拿到一个前缀，下面可分 16~256 个 /64 | 最佳，可做真随机 |
| 单个 `/64`（SLAAC） | 光猫只有一个子网 | 可行，但只能同段换后缀 |
| 没有 IPv6 | 光猫关了 IPv6 或运营商没给 | 需要先开 IPv6 |

常见运营商前缀分配：`240e:`（电信）`2409:`（移动）`2408:`（联通）`240x:x:y::/60` 类似形态。

## 4. 方案 A（推荐·本工具零改动）：Linux 出口设备 SNAT 地址池

适用：**运行本工具的机器本身就是出口**（直接拨号/桥接），或你是某台 Linux 网关的管理员。

原理：把前缀配置成"首尾区间"，出站新建连接由内核从区间取一个未占用的源地址。每个新 SOCKS5 请求 = 新 TCP 连接 = 新出口 IP，本工具完全无感知。

```bash
# 1. 在 WAN 网卡上把 16 个 /64 各配一个地址（/60 的例子）
for i in $(seq 0 15); do
  ip -6 addr add "240e:x:y:${i}::1/64" dev wan0
done

# 2. 出站 SNAT 到整个地址区间（跨多个 /64）
ip6tables -t nat -A POSTROUTING -o wan0 \
  -j SNAT --to-source 240e:x:y:0::1-240e:x:y:f:ffff

# 3. 查看当前连接用的出口
curl -6 https://api64.ipify.org
```

每次新建连接内核都会尝试取池内未占用地址 → 多连接时出口自然分散。用 `conntrack` 可确认：`conntrack -L | grep -i 240e:x:y:`

## 5. 方案 B：应用层绑定（Windows / 需要可控随机）

适用：本工具跑在 **Windows**（本项目默认场景），或你想精确控制每个连接。

Windows 没有 SNAT 区间这招，但可以把多个地址配到网卡，让本工具每连接 bind 一个：

```powershell
# 网卡上配多个 /64 地址（管理员 PowerShell）
netsh interface ipv6 add address "以太网" 240e:x:y:0::1/64
netsh interface ipv6 add address "以太网" 240e:x:y:1::1/64
# ... 16 个 /64 各配一个

# 查看
netsh interface ipv6 show address
```

本工具连接池已留扩展点，在 `lib/pool/connection-pool.js` 的 `_connectOne` 传入 `localAddress` 即可实现每连接绑定不同源地址（轮换/随机）。

## 6. 做实的关键：跨 /64 才叫"完全不同"

部分服务按 **/64 前缀段** 进行来源归类。只在同一个 /64 里换后缀（`::1`~`::ffff`），对此类站点仍是"同一来源段"。

- 要让出口看起来彻底无关，地址要**散布到不同 /64**（方案 A 的 SNAT 区间跨 16 个 /64 就是这个目的）。
- /60 = 16 个独立 /64 段；/56 = 256 个，随机性更充足。

## 7. 验证方法

```bash
# 连续访问，观察 IP 是否变化
for i in $(seq 1 10); do curl -6 https://api64.ipify.org; sleep 1; done

# 检查你的出口 IPv6 与前缀是否同段（应落在 240e:x:y:0::/60 内）
curl -6 https://ifconfig.co

# 经本工具代理访问 opencode（确认走 IPv6 且每次不同）
curl -6 -x socks5h://127.0.0.1:7890 https://opencode.ai -o /dev/null -w "%{remote_ip}\n"
```

## 8. 常见坑

- **只有单个 /64 时换后缀**：可行但对按段识别的站点无效；且部分运营商对同 /64 大量并发连接有临时限制。
- **IPv4 别想这条路**：单条 PPPoE 通常就 1 个公网 IPv4，多 IPv4 需要双拨/多条链路，本工具层面无解。
- **IPv6 临时地址（隐私扩展 RFC 8981）**：系统自带的临时地址几小时才换一次，不是按连接换，达不到目的。
- **本工具在内网、公网在路由器上**：地址池要在路由器（出口设备）上做，本工具所在机器上配再多也没用。
- **池地址别被防火墙拦**：确认出站没被 ACCEPT 前的规则挡掉；用 `ip6tables -L -t nat` 检查。

## 9. 对本工具代码的影响

- 方案 A：**零改动**，本工具完全透明。
- 方案 B：改动极小，仅连接池新增"源地址池 + 轮换"，DNS/缓存/转发均不动。
